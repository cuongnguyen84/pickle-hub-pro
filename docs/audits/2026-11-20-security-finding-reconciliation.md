## Priority and required evidence

1. **Highest priority: recovery bearer-token disclosure after CAPTCHA (M9).** At this source snapshot any caller with a valid Turnstile solve and a matching phone can reach a response carrying the existing magic token; the inspected handler does not bind that caller to phone ownership. This is source evidence, not a statement that production was exploited. Preserve legitimate guest recovery by using an owned delivery channel or verified OTP/session before issuing credentials; never treat CAPTCHA as identity proof. Add negative tests for another person's phone, no-channel registrations, expired tokens, replay and uniform responses. Review all registration token RPCs alongside M6.
2. Parser-grade SSR sanitization; strict scheme checks across native callbacks and href sinks; complete token lifecycle/rotation with compatibility plan.
3. Atomic rate limits with explicit failure policy; scraper redirect/size restrictions; complete admin router boundary, then CSP tightening.
4. Attach current deployed-source hashes/version IDs and read-only catalog results per row. Stage any behavioral tests that can send notifications or alter registrations. A green build, migration-ledger parity or historical LIVE badge is insufficient.
