# Migration drift: 20260824100000_venue_price_hours

**Ngày:** 2026-08-24 · **Trạng thái:** đã sửa · **Ảnh hưởng:** `deploy-guard` đỏ 3 commit liên tiếp

## Triệu chứng

`deploy-guard` fail ở bước **Migration drift check (strict — SEC-06)**, bắt đầu từ
`283b735` (#665) và kế thừa sang mọi commit sau — gồm `7c110c8`, một commit chỉ đụng
CSS và JSX, không liên quan gì tới database. Đó là dấu hiệu nhận biết: khi một commit
không đụng `supabase/` mà vẫn fail drift check, lỗi nằm ở trạng thái DB chứ không ở commit.

## Nguyên nhân

File `supabase/migrations/20260824100000_venue_price_hours.sql` có trong repo, và toàn bộ
nội dung của nó **đã được áp dụng thật** lên database — nhưng **không có bản ghi tương ứng**
trong `supabase_migrations.schema_migrations`. Tức là ai đó chạy SQL thẳng lên DB
(dashboard hoặc Management API) thay vì qua migration runner.

Đã verify từng thành phần của file trước khi kết luận, chứ không suy từ việc "cột có tồn tại":

## Vì sao phải verify hết file trước khi repair

`migration repair --status applied` đánh dấu **toàn bộ** file là đã chạy. Nếu file còn phần
chưa thực sự chạy trên DB, lệnh đó **giấu luôn phần thiếu** thay vì sửa — gate xanh lại
nhưng schema vẫn sai, và lần sau không còn tín hiệu nào để phát hiện. Chỉ an toàn khi đã
đối chiếu từng thành phần như bảng trên.
