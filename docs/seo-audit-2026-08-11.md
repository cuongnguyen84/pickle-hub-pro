Method: live Googlebot-UA `curl` against prod + codebase root-cause (seo-specialist
pass). Baseline is already strong: SSR prerender, 11-segment sitemap index with
hreflang, blog-post schema (BlogPosting + FAQPage + BreadcrumbList + ImageObject),

## Fixed in this pass (branch `seo/blog-index-jsonld-home-h1`, cache `pr:v40`)

- **Blog index JSON-LD (was MEDIUM).** `/blog` and `/vi/blog` emitted zero
  structured data. Added `ItemList` (posts) + `BreadcrumbList` in a single
  `@graph`, matching the `ItemList` convention in `social-list.ts` / `venues.ts`.
  `functions/_lib/render/blog.ts` — `renderBlog()` + `renderViBlogIndex()`.
  Note: `CollectionPage`/`ItemList` on a list page is **entity context**, not a
  rich-result trigger — bots already saw the links + title + hreflang, so this is
  a signal improvement, not an indexation fix.
- **Duplicate H1 on homepages (MEDIUM).** `/` and `/vi` shipped two `<h1>`
  (auto header from `buildHtml(title)` + a manual body `<h1>`). Added
  `omitAutoHeader: true` to both `home.ts` calls, keeping the single body H1.
  Low impact (Google tolerates multi-H1) but a cheap correctness fix.

## Deferred — DO NOT "fix" without the stated condition

- **[#1] EN homepage `<title>` = "ThePickleHub" (12 chars, no keyword).**
  This is **intentional**, not a bug. Set 2026-08-08 (PR #560/#562, cache
  v37→v38). Comment lives in `functions/_lib/render/home.ts` near the `title`
  const: *"Keep the homepage identity identical to the verified OAuth app name."*
  Changing it to a keyword title (e.g. "Pickleball Asia — Tournaments…") would
  make the homepage title diverge from the Google OAuth app name and **risks
  failing OAuth verification**. Product positioning is instead carried by the
  meta `description` + `Organization.alternateName` (which rescues brand queries
  like "the pickle hub"). **Revisit only after Google OAuth verification is
  confirmed complete**, then a keyword-bearing EN title becomes safe.
  → Lesson: `git log -3 <file>` before ranking any finding HIGH. The heaviest
    "finding" this audit surfaced was a deliberate change from 3 days earlier.

- **[#4] Homepage hreflang built via `extraMeta` string** instead of the
  `alternates` param of `buildHtml()` (used by venues/static-pages). Tech debt
  (MEDIUM-low): fold in whenever `home.ts` hreflang is next touched.

- **og:image on tournament/venue/rankings is the static `og-image.png`** despite
  the dynamic `og-*` edge functions existing. Possibly deliberate (SSR latency /
  edge-function cost). Confirm the reason before wiring dynamic OG into SSR meta.
