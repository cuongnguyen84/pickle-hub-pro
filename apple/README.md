# ThePickleHub — Native iOS (SwiftUI)

Full-native SwiftUI rewrite of ThePickleHub. **Reuses the existing Supabase
backend unchanged** — only the client layer is native. The Capacitor wrapper in
`../ios/` stays the shipping app until this reaches feature parity.

- Min target: **iOS 17**
- Language mode: **Swift 6**, with complete strict-concurrency diagnostics in Release.
- Debug bundle id: `net.thepicklehub.app.dev`; Release bundle id:
  `net.thepicklehub.app` (replaces the current Capacitor app).
- Native release version: `1.1.0 (3)`, following Capacitor `1.0.1 (2)`.
- Project is generated by **XcodeGen** from `project.yml` — the `.xcodeproj` is
  git-ignored. Edit `project.yml`, not the project in Xcode.

## Setup

```sh
brew install xcodegen          # one-time
cd apple
cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig   # then fill in values
xcodegen generate
open ThePickleHub.xcodeproj
```

Build/run from CLI. **DerivedData + SPM checkouts are kept on the external
volume** to spare the main disk (which is tight):

```sh
xcodegen generate
xcodebuild -scheme ThePickleHub \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -derivedDataPath /Volumes/CMBackup/picklehub-ios/DerivedData build
```

> The iOS Simulator runtime (~8GB) lives on the boot volume under
> `/Library/Developer/CoreSimulator` — Apple does not support relocating it.
> Only build output is offloaded.

## Tests

Generate the project, then run the native unit-test bundle on any available
iPhone simulator:

```sh
cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig # first run only
xcodegen generate
xcodebuild test \
  -project ThePickleHub.xcodeproj \
  -scheme ThePickleHub \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  CODE_SIGNING_ALLOWED=NO
```

The `Apple tests` GitHub Actions workflow runs the same test bundle for every
pull request or push to `main` that changes `apple/**`. It generates the
ignored `.xcodeproj` and a placeholder secrets file from the checked-in
examples, so CI does not require production credentials.

CI also runs `scripts/release_preflight.sh`, uses the checked-in transitive
`Config/Package.resolved`, and builds the Release configuration with complete
strict-concurrency diagnostics. See `docs/RELEASE_AND_ACTIVATION.md` before any
archive, TestFlight upload or native-registration activation.

Release parity includes Firebase Messaging 12.9.0 (APNs → FCM → `push_tokens`).
It is fail-closed and OFF in checked-in config until signed-device smoke. Shipping
also requires explicit approval that existing Capacitor users sign in once after
the update because the old WebKit session cannot be read as a native Keychain
session.

## Authentication

Native authentication supports:

- Sign in with Apple through `AuthenticationServices` + a SHA-256 nonce.
- Native Google Sign-In.
- Email/password and phone OTP.

All methods establish the same persisted Supabase session. Apple capability and
Supabase Client ID activation steps are documented in
`docs/RELEASE_AND_ACTIVATION.md`.

If both probes pass with a real account, the architecture is validated.
